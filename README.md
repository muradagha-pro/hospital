# نظام استدعاء الممرضة — دليل التشغيل خطوة بخطوة

هاي أبسط نسخة من النظام: المريض يضغط زر "استدعاء الممرضة"، والممرضة تشوف الطلب فوراً على شاشتها وتضغط "استلام" ثم "تم التنفيذ". كل شي بيصير مباشرة (Real-time) بدون تحديث الصفحة.

**الوقت المتوقع لأول تشغيل: 20-25 دقيقة، بدون أي كتابة كود أو استخدام Terminal.**

---

## الخطوة 1: إنشاء مشروع Firebase (قاعدة البيانات، مجانية)

1. افتح المتصفح وروح لـ: https://console.firebase.google.com
2. سجّل دخول بحساب Google.
3. اضغط **"Add project" / "إضافة مشروع"**.
4. أعطِ المشروع اسم، مثلاً: `nurse-call-system`.
5. عطّل خيار Google Analytics (مو ضروري) واضغط **Create project**.

## الخطوة 2: تفعيل قاعدة البيانات Firestore

1. من القائمة الجانبية اليسرى، اضغط **Build → Firestore Database**.
2. اضغط **Create database**.
3. اختر **Start in test mode** ثم Next.
4. اختر أقرب موقع خادم لك (مثلاً `eur3` لأوروبا) واضغط **Enable**.

> ملاحظة: "test mode" يخلي القاعدة مفتوحة لمدة 30 يوم فقط للتجربة. بآخر الدليل رح أعطيك قواعد أمان بسيطة لتفعيلها قبل الاستخدام الفعلي مع المرضى.

## الخطوة 3: ربط الموقع بمشروع Firebase

1. من نفس صفحة المشروع، اضغط أيقونة **الترس ⚙️ (Project settings)** أعلى اليسار.
2. انزل لتحت لقسم **"Your apps"** واضغط أيقونة **</> (Web)**.
3. أعطِ اسم مثل `nurse-call-web` واضغط **Register app**.
4. رح تظهرلك قطعة كود فيها كائن اسمه `firebaseConfig` يشبه هيك:

```js
const firebaseConfig = {
  apiKey: "AIzaSy...",
  authDomain: "nurse-call-system.firebaseapp.com",
  projectId: "nurse-call-system",
  storageBucket: "nurse-call-system.appspot.com",
  messagingSenderId: "123456789",
  appId: "1:123456789:web:abcdef"
};
```

5. افتح ملف **`firebase-config.js`** المرفق معك، واستبدل القيم `"ضع_القيمة_هون"` بالقيم الحقيقية اللي ظهرتلك (انسخ/الصق كل قيمة بمكانها المطابق).
6. احفظ الملف.

## الخطوة 4: رفع الموقع أونلاين مجاناً (بدون أي أوامر Terminal)

رح نستخدم **Netlify Drop** — بس تسحب المجلد وبيصير عندك رابط شغّال.

1. روح لـ: https://app.netlify.com/drop
2. (اختياري) سجّل حساب مجاني عشان الموقع ما ينحذف بعد فترة — بدون حساب بيضل شغال بس مؤقت.
3. اسحب **مجلد المشروع كامل** (اللي فيه كل الملفات: patient.html, nurse.html, إلخ) وفلته داخل المربع المكتوب فيه "Drag and drop".
4. خلال ثوانٍ رح يعطيك رابط شبيه بـ: `https://curious-tulip-123.netlify.app`
5. هذا هو رابط موقعك. احتفظ فيه.

## الخطوة 5: إنشاء رموز QR لكل غرفة

رابط صفحة المريض بيكون بهاي الصيغة، وبس تغيّر رقم الغرفة بالنهاية:

```
https://curious-tulip-123.netlify.app/patient.html?room=101
https://curious-tulip-123.netlify.app/patient.html?room=102
https://curious-tulip-123.netlify.app/patient.html?room=103
```

استخدم أي موقع مجاني لتوليد QR، مثل:
- https://www.qr-code-generator.com
- https://www.the-qrcode-generator.com

بس تولّد رمز لكل رابط (رابط غرفة)، تطبع الرموز وتحطها بكل غرفة.

## الخطوة 6: صفحة الممرضة

رابط الممرضة ثابت وما بيتغير:

```
https://curious-tulip-123.netlify.app/nurse.html
```

افتحيه على أي موبايل أو تابلت أو جهاز عند محطة التمريض، سجّلي اسمك مرة وحدة، وخلّيه مفتوح طول الدوام. أي طلب جديد رح يظهر فوراً.

## الخطوة 7: أول اختبار

1. افتح `nurse.html` على جهاز (أو تبويب متصفح) وسجّلي اسم.
2. افتح `patient.html?room=101` على جهاز ثاني (أو تبويب خفي/incognito).
3. اضغط "استدعاء الممرضة" من صفحة المريض.
4. لازم يظهر الطلب فوراً بصفحة الممرضة، وتقدري تضغطي "استلام الطلب" ثم "تم التنفيذ"، وتشوفي التحديث فوراً برجوع بصفحة المريض.

> **مهم:** أول مرة تفتحي فيها `nurse.html`، ممكن يطلع خطأ بالـ Console يقول إنه محتاج "index" (فهرس) لأن الاستعلام يفلتر حالتين ويرتب بالوقت مع بعض. الخطأ نفسه بيجيب رابط مباشر لإنشاء الفهرس بضغطة واحدة على Firebase — افتحي الرابط، اضغطي Create Index، انتظري دقيقة، وبيشتغل تلقائياً بعدها.

## قبل الاستخدام الفعلي مع مرضى حقيقيين: تأمين القاعدة

هلق القاعدة مفتوحة للجميع (test mode). قبل ما تعتمدوا النظام فعلياً، روحي لـ **Firestore Database → Rules** واستبدلي القواعد بهاي:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /callRequests/{requestId} {
      allow read: if true;
      allow create: if request.resource.data.status == "sent"
                    && request.resource.data.room is string;
      allow update: if request.resource.data.status in ["received", "done"];
      allow delete: if false;
    }
  }
}
```

هاي القواعد بتسمح بإنشاء طلبات وتحديث حالتها بس، بدون حذف أو تعديل غير مصرح فيه. للاستخدام الإنتاجي الكامل بمستشفى حقيقي، الأفضل إضافة تسجيل دخول (Firebase Authentication) لطاقم التمريض بدل الاسم النصي فقط — قدر أساعدك فيها لما توصل لهاي المرحلة.

## شو بعدين؟ (الخطوات الجاية حسب النظام الأصلي)

هاي بس جزء "استدعاء الممرضة". الخطوات الجاية المتوافقة مع فكرتك الأصلية:

1. **صيانة وشكاوى**: نفس فكرة زر الاستدعاء، بس بنوع طلب مختلف (`type: "maintenance"` أو `"complaint"`).
2. **الكافتيريا**: صفحة فيها قائمة منتجات (تُدار من لوحة مدير)، والمريض يختار ويرسل طلب، وتطبيق كافتيريا مشابه لتطبيق الممرضة بس بحالات: تم الاستلام → قيد التجهيز → جاهز → تم التسليم.
3. **لوحة الإدارة**: صفحة ويب فيها جدول لكل الطلبات + فلاتر وإحصائيات، وربط الطوابق/الغرف/الموظفين.
4. **تسجيل دخول حقيقي للموظفين** عبر Firebase Authentication بدل إدخال الاسم فقط.
5. **تصعيد تلقائي** لو ما استلم أحد الطلب خلال دقيقتين مثلاً (يحتاج Cloud Function بسيطة).

قولّي أي جزء بدك نبنيه بعدين وبنكمل عليه بنفس الطريقة.
