# نظام استدعاء الممرضة في المستشفى — دليل المستخدم الكامل

## نظرة عامة على النظام

هذا نظام شامل لإدارة المستشفيات يمكّن المرضى من طلب مساعدة التمريض، ويسمح للممرضات بإدارة الطلبات بكفاءة، ويوفر للمديرين تحليلات فورية، ويشمل نظام طلب الكافتيريا.

---

## الصفحات الرئيسية والعمليات

### 1. **صفحة المريض** (`patient.html?room=XXX`)

**الغرض:** واجهة غرفة المريض لطلب مساعدة الممرضة

**عملية الاستخدام:**
- يقوم المريض بمسح رمز QR الذي يتضمن رقم غرفته (مثال: `patient.html?room=204`)
- الصفحة تعرض:
  - رقم الغرفة
  - تحديد القسم تلقائياً بناءً على رقم الغرفة
  - **زر استدعاء كبير** لاستدعاء الممرضة
  - مؤشر حالة فوري يظهر ما إذا تم استلام الطلب وتعيينه لممرضة
  - رابط لنموذج التعليقات والاقتراحات

**تعيين الأقسام:**
يتم تحديد الأقسام تلقائياً حسب نطاقات أرقام الغرف (معرّفة في `departments.js`):
- الطوارئ: الغرف 101–199
- الطب الباطني: الغرف 201–299
- الجراحة: الغرف 301–399
- طب الأطفال: الغرف 401–499
- النسائية والولادة: الغرف 501–599
- العناية المركزة: الغرف 601–699

---

### 2. **صفحة محطة التمريض** (`nurse.html?dept=XXX`)

**الغرض:** واجهة مخصصة لموظفي التمريض لاستقبال وإدارة الطلبات

**عملية الاستخدام:**
1. تمسح الممرضة رمز QR لقسمها (مثال: `nurse.html?dept=internal`)
2. تدخل اسمها (إدخال بسيط، بدون مصادقة)
3. ترى فقط الطلبات الخاصة بقسمها المعيّن
4. الميزات:
   - **تنبيهات الطلبات الواردة:** جرس صوتي + اهتزاز (يتكرر حتى الاستلام)
   - **قائمة الطلبات:** عرض الطلبات المعلقة في الوقت الفعلي
   - **إجراءات قبول/إنهاء:** تعليم الطلبات كمستلمة ومكتملة
   - **تبويب سجل اليوم:** جميع الطلبات المعالجة خلال الدوام مع:
     - تفاصيل الطلب
     - طوابع زمنية
     - إمكانية إضافة/تعديل ملاحظات لكل طلب
   - **إشعارات المتصفح الاختيارية** للطلبات الجديدة

**سير حالة الطلب:**
- **مُرسل:** الطلب الأولي من المريض
- **مستلم:** تأكيد الممرضة استلام الطلب
- **مكتمل:** انتهاء معالجة الطلب

---

### 3. **صفحة التعليقات والشكاوى** (`feedback.html?room=XXX`)

**الغرض:** السماح للمرضى بتقديم شكاوى أو اقتراحات

**عملية الاستخدام:**
1. يتم الكشف التلقائي عن غرفة المريض من معامل URL
2. يختار المريض نوع التعليق (شكوى أو اقتراح)
3. يدخل العنوان والرسالة
4. يُرسل مباشرة إلى الإدارة
5. يظهر في لوحة الإدارة للمراجعة

---

### 4. **لوحة التحكم الإدارية** (`admin.html`)

**الغرض:** تحليلات فورية ومراقبة الأداء لمديري المستشفى

**عملية الاستخدام:**
1. الوصول عبر رابط ثابت (بدون مصادقة مطلوبة في الإصدار الحالي)
2. خيارات العرض:
   - التبديل بين "اليوم" و"آخر 7 أيام"
3. عرض المقاييس:
   - **بطاقات الملخص:**
     - إجمالي الاستدعاءات المستلمة
     - الطلبات المكتملة
     - الطلبات المعلقة
     - متوسط وقت الاستجابة (على مستوى المستشفى)
   - **تفصيل حسب القسم:**
     - عدد الاستدعاءات لكل قسم
     - متوسط وقت الاستجابة لكل قسم
   - **سجل ملاحظات الممرضات:**
     - جميع الملاحظات من جميع الأقسام
     - مرتبة حسب الأحدث أولاً
     - تتضمن تفاصيل الطلب والطوابع الزمنية
   - **قسم التعليقات:**
     - جميع شكاوى واقتراحات المرضى
     - منظمة ومعروضة للمراجعة الإدارية

**ملاحظة الأمان:** مفتوحة حالياً بدون تسجيل دخول. قبل النشر الفعلي على شبكة المستشفى الحقيقية، قم بتطبيق مصادقة Firebase لتقييد الوصول.

---

### 5. **صفحة إدارة الأقسام** (`admin-departments.html`)

**الغرض:** تكوين أقسام المستشفى وتعيين الغرف

**عملية الاستخدام:**
1. الوصول عبر رابط ثابت
2. الوظائف الإدارية:
   - **عرض الأقسام:** رؤية جميع الأقسام المُعيّنة حالياً
   - **إضافة قسم:** إنشاء قسم جديد مع:
     - اسم القسم
     - رمز/معرّف القسم
     - نطاق أرقام الغرف (من/إلى)
   - **تحرير القسم:** تعديل نطاقات الغرف
   - **حذف القسم:** إزالة الأقسام
3. الرجوع التلقائي: إذا لم يتم تكوين أقسام مخصصة، يستخدم النظام الأقسام الافتراضية من `departments.js`

---

### 6. **إدارة منتجات الكافتيريا** (`cafeteria-products.html`)

**الغرض:** واجهة إدارية لإدارة أصناف قائمة الكافتيريا

**عملية الاستخدام:**
1. الوصول إلى الصفحة لإدارة مخزون الكافتيريا
2. إضافة منتجات جديدة مع:
   - اسم المنتج
   - السعر
   - الوصف/الفئة
3. تحرير المنتجات الموجودة
4. إزالة المنتجات من القائمة
5. التغييرات متاحة فوراً لطلبات المرضى

---

### 7. **طلب الكافتيريا للمريض** (`cafeteria-order.html?room=XXX`)

**الغرض:** السماح للمرضى بطلب الطعام/المواد من الكافتيريا

**عملية الاستخدام:**
1. يمسح المريض رمز QR برقم غرفته (مثال: `cafeteria-order.html?room=201`)
2. يستعرض منتجات الكافتيريا المتاحة
3. يختار العناصر والكميات
4. يراجع الطلب مع:
   - تفاصيل العنصر
   - توزيع السعر
   - التكلفة الإجمالية
5. يُرسل الطلب
6. يتم إعادة التوجيه إلى صفحة تتبع حالة الطلب (`cafeteria-order-status.html`)

---

### 8. **حالة طلب الكافتيريا** (`cafeteria-order-status.html?room=XXX&orderId=XXX`)

**الغرض:** تتبع فوري لطلبات الكافتيريا للمرضى

**عملية الاستخدام:**
1. عرض حالة الطلب الحالية مع مؤشر تقدم مرئي
2. عرض خطوات الحالة:
   - **تم الاستلام:** تسجيل الطلب في نظام الكافتيريا
   - **قيد التحضير:** المطبخ يحضر الطلب
   - **تم التسليم:** الطلب جاهز/تم تسليمه للغرفة
3. عرض:
   - الوقت المقدر للتحضير
   - الوقت المتبقي للتسليم
   - محتويات الطلب والتوزيع
   - التكلفة الإجمالية
4. التحديثات الفورية عند قيام موظفي الكافتيريا بتحديث حالة الطلب

---

### 9. **صفحة إدارة الكافتيريا** (`cafeteria.html`)

**الغرض:** واجهة موظفي الكافتيريا لإدارة وتنفيذ الطلبات

**عملية الاستخدام:**
1. الوصول إلى رابط مخصص لموظفي الكافتيريا
2. عرض الطلبات الواردة:
   - رقم غرفة المريض
   - محتويات الطلب والتفاصيل
   - طابع وقت تقديم الطلب
3. تحديث حالة الطلب:
   - تعليم "تم الاستلام" عند وصول الطلب للمطبخ
   - تعليم "قيد التحضير" أثناء العمل على الطلب
   - تعليم "تم التسليم" عند الانتهاء/إرسال الطلب للغرفة
4. مراقبة قائمة الانتظار والتنفيذ
5. يمكن للموظفين ترتيب الأولويات وإدارة سير العمل بكفاءة

---

### 10. **صفحة الهبوط/الاختبار** (`index.html`)

**الغرض:** صفحة هبوط مؤقتة مع روابط اختبار (للتطوير/الاختبار فقط)

**عملية الاستخدام:**
1. عرض روابط لاختبار صفحات مختلفة:
   - غرف مريض عينة (الطب الباطني)
   - محطة التمريض (الطب الباطني)
   - إدارة الكافتيريا
   - لوحة التحكم الإدارية
2. للإنتاج: استبدل برابط رمز QR مباشر أو احذفها تماماً

## كيفية النشر والاستخدام

### الخطوة 1: تكوين Firebase
- قم بإنشاء مشروع Firebase وقاعدة بيانات Firestore
- أضف بيانات اعتماد Firebase إلى `firebase-config.js`
- انشر الاستضافة على Netlify أو Firebase Hosting

### الخطوة 2: تكوين الأقسام
- زر `admin-departments.html` لتخصيص الأقسام
- أو استخدم الأقسام الافتراضية من `departments.js`:
  - الطوارئ: 101–199
  - الطب الباطني: 201–299
  - الجراحة: 301–399
  - طب الأطفال: 401–499
  - النسائية والولادة: 501–599
  - العناية المركزة: 601–699

### الخطوة 3: توليد رموز QR

**لغرف المرضى:**
- أنشئ رموز QR لكل غرفة:
  ```
  https://your-site.netlify.app/patient.html?room=201
  https://your-site.netlify.app/patient.html?room=202
  ...إلخ
  ```

**لمحطات التمريض:**
- رمز QR واحد لكل قسم:
  ```
  https://your-site.netlify.app/nurse.html?dept=emergency
  https://your-site.netlify.app/nurse.html?dept=internal
  https://your-site.netlify.app/nurse.html?dept=surgery
  https://your-site.netlify.app/nurse.html?dept=pediatrics
  https://your-site.netlify.app/nurse.html?dept=obgyn
  https://your-site.netlify.app/nurse.html?dept=icu
  ```

### الخطوة 4: إعداد الكافتيريا
1. أولاً، أضف المنتجات عبر `cafeteria-products.html`
2. أنشئ رموز QR لطلب المرضى:
   ```
   https://your-site.netlify.app/cafeteria-order.html?room=201
   ```
3. انشر رابط `cafeteria.html` في محطة الكافتيريا لإدارة الطلبات

### الخطوة 5: تأمين قواعد Firestore

استبدل قواعد Firestore بـ:
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /callRequests/{requestId} {
      allow read: if true;
      allow create: if request.resource.data.status == "sent"
                    && request.resource.data.room is string
                    && request.resource.data.department is string;
      allow update: if request.resource.data.status in ["received", "done"]
                    || ("note" in request.resource.data);
      allow delete: if false;
    }
  }
}
```

### الخطوة 6: نشر فهارس Firestore

استخدم Firebase CLI:
```bash
firebase deploy --only firestore:indexes
```

أو اتبع الرابط المقدم من Firebase في المتصفح عند أول تحميل للصفحات.

## توصيات الأمان

**الحالة الحالية:**
- لوحة الإدارة مفتوحة حالياً (لا يوجد تسجيل دخول مطلوب)
- هذا مقبول للاختبار لكن ليس للاستخدام الفعلي في الإنتاج

**قبل النشر المباشر على شبكة المستشفى:**
1. طبّق مصادقة Firebase لصفحات الإدارة
2. أضف التحكم في الوصول بناءً على الأدوار (تقييد من يمكنه الوصول إلى ميزات الإدارة)
3. فعّل HTTPS (تلقائي مع Netlify/Firebase Hosting)
4. راجع واختبر قواعد أمان Firestore
5. طبّق تسجيل الأنشطة الإدارية

---

## التحسينات المستقبلية

1. **المصادقة:** إضافة مصادقة Firebase لصفحات الإدارة
2. **الوصول بناءً على الأدوار:** تحديد الأذونات لأدوار الموظفين المختلفة
3. **التصعيد التلقائي:** تنبيهات تلقائية إذا لم يتم الرد على الطلب خلال وقت محدد
4. **تحليلات الأداء:** تقارير محسّنة وتحليل الاتجاهات
5. **دعم متعدد اللغات:** التوسع خارج اللغة العربية والإنجليزية

---

## الدعم

للأسئلة حول صفحات أو وظائف معينة، راجع وصف الصفحات الفردية أعلاه. لكل صفحة سير عملية واضح وغرض محدد.

**بالتوفيق مع نشر نظام المستشفى الخاص بك!** إذا كنت بحاجة إلى ميزات أو تعديلات إضافية، أخبرني.
